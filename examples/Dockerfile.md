# Dockerfile: что за чем

Dockerfile описывает сборку образа. **Образ** — шаблон, **контейнер** — запущенный из него процесс с окружением.

## Небольшой пример

```dockerfile
FROM python:3.13-slim
WORKDIR /app

# Зависимости меняются реже, чем исходный код.
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .
USER 10001
EXPOSE 8000
CMD ["python", "app.py"]
```

Это схема для приложения, которое слушает порт 8000. В реальном проекте проверь права на файлы и каталоги, нужные пользователю 10001.

## Как читать директивы

| Директива | Смысл |
| --- | --- |
| FROM | Базовый образ, начало стадии сборки |
| WORKDIR | Рабочая папка следующих инструкций |
| COPY | Скопировать файлы из контекста сборки |
| RUN | Выполнить команду во время сборки |
| ENV | Задать переменную окружения |
| ARG | Параметр сборки; не место для секретов |
| USER | Пользователь следующих RUN и запуска контейнера |
| EXPOSE | Описать порт; сам по себе не публикует его |
| CMD | Команда по умолчанию при запуске |
| ENTRYPOINT | Основная команда контейнера |

Строгого общего порядка для всех директив нет: порядок влияет на результат и кеш. Обычно сначала копируют описание зависимостей и устанавливают их, затем копируют часто меняющийся код.

## Собрать и запустить

```bash
docker build -t my-app .
docker run --rm -p 8000:8000 my-app
```

Точка — контекст сборки. `-p 8000:8000` публикует порт контейнера на хосте.
